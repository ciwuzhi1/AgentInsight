# 后端测试说明

盘点范围：`backend/tests/**/*.py`（只读，不改测试逻辑）。

约定：

- 单测/集成测试均**不依赖 MySQL / Docker / 网络**（见 `tests/conftest.py`）；Redis、DB 用 Fake/mock。
- `conftest.py` 把 `backend/` 加入 `sys.path`，可直接 `import app.*`。
- 工作目录：`D:\Development\aiproject\AgentInsight\backend`。

## 1. 测试清单

### unit（`tests/unit/`，纯逻辑 / mock）

| 文件 | 用途（一行） |
|------|----------------|
| `test_state.py` | TaskState 状态机：合法迁移、非法迁移、终态、重试耗尽 |
| `test_planner.py` | 计划模板结构、拓扑序；`validate_dag` 拒绝环/缺依赖/超步数 |
| `test_executor.py` | 波次并行、重试、optional 跳过、AgentMessage、max_steps 拒绝 |
| `test_registry.py` | AgentRegistry 注册/获取/覆盖/单例 |
| `test_taskbus.py` | 事件总线截断回放、TTL 清扫、step 序号映射 |
| `test_complexity.py` | 复杂度评估边界 + 自适应 `build_data_plan` 步数 |
| `test_router.py` | 数据引擎路由：小表 DuckDB、过大拒绝、阈值边界 |
| `test_sql_guard.py` | SQL Guard：CTE/空白放行，黑名单/多语句/PRAGMA 拒绝，LIMIT 改写 |
| `test_mock_llm.py` | `MockLLMClient` 规则版 NL2SQL（group/avg/top-N/total/兜底） |
| `test_resume_parse.py` | ResumeAgent TXT 正则兜底 profile；缺失文件报错 |
| `test_match.py` | MatchAgent：规则打分区间、同义词归一、缺口、mock 解读 |
| `test_match_algo.py` | TF-IDF + 余弦相似度、技能覆盖率、综合分（全离线） |
| `test_report.py` | report_agent：match/data 报告文案、亮点、建议、run 写回 |
| `test_validator.py` | ValidatorAgent：report 校验、score-dimensions 一致性、非法 match |
| `test_few_shot.py` | few-shot 检索：增删、LRU 500、中文 bigram、导入导出 |
| `test_context.py` | token 估算、预算截断、resume/job/schema/result 压缩、prompt 组装 |
| `test_crawler_run.py` | 爬虫 run 韧性：max_items、逐条 upsert、失败跳过、failed_urls |
| `test_evaluation.py` | 评测用例加载/去重、routing 三类判定、metrics、NL2SQL mock |
| `test_security.py` | 密码哈希、JWT 往返/过期/篡改、用户 CRUD、数据集用户隔离 |
| `test_enterprise.py` | 限流器、结构化 JSON 日志、任务 query 长度截断 |

### integration（`tests/integration/`，跨模块 / mock 依赖）

| 文件 | 用途（一行） |
|------|----------------|
| `test_workflow.py` | TaskState → planner → Supervisor/Executor 全链路（mock agents） |
| `test_agent_workflow.py` | mock LLM + 真实 ReportSynthesizer 全链路（数据/匹配链） |
| `test_context_integration.py` | 真实 agent 输出 → 上下文构建 → token 预算 → 压缩比 |
| `test_cache_integration.py` | cache-aside 端到端、LLM 调用计数、故障降级、TTL 策略、幂等锁、缓存原语（FakeRedis） |
| `test_api.py` | POST/GET `/api/tasks`、SSE 事件流、401 鉴权 |
| `test_api_v3_endpoints.py` | DELETE dataset、GET jobs 分页、health/duckdb、导出 CSV/JSON、简历详情 |
| `test_api_matches_models.py` | POST /api/matches 全分支（鉴权/校验/隔离/限流/幂等锁/成功）；/api/models 列表脱敏、加密落库、激活、删除、连通性测试 |
| `conftest.py` | 集成测试公共夹具：`client`（TestClient，lifespan 轻量化）、`auth_headers` |

共 20 个 unit 文件 + 8 个 integration 文件 + 2 个 `conftest.py`（`tests/` 与 `tests/integration/`）。

CI（`.github/workflows/ci.yml`）执行 `python -m pytest tests -q`，即单测 + 集成测试全跑；
依赖真实 MySQL 的少数用例自带 `skipif`，CI 中自动跳过。

## 3. 如何运行

在 `backend` 目录下：

```bash
# 示例：单个文件（任务指定示例）
python -m pytest tests/unit/test_crawler_run.py -q

# 单个文件（integration）
python -m pytest tests/integration/test_api.py -q

# 单个用例
python -m pytest tests/unit/test_state.py::test_happy_path_transitions -q

# 整层
python -m pytest tests/unit -q
python -m pytest tests/integration -q

# 全量
python -m pytest tests -q

# 名称过滤
python -m pytest tests -k "cache" -q
```

说明：

- 无需额外配置文件（无 `pytest.ini`/`pyproject.toml`）；依赖见 `backend/requirements.txt`。
- 默认离线可跑；若本地 venv 在 `backend/.venv`，先激活再执行上述命令。
