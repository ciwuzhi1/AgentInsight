# AgentInsight 架构说明

> **一句话**：上传数据/简历 → 中文提问或勾选岗位 → 多 Agent 分析 → 产出 SQL、图表与匹配解读。
>
> **技术栈**：Next.js 15 · FastAPI · MySQL · Redis（可选）· DuckDB · 智谱 GLM

## 1. 项目是什么

| 能力 | 说明 |
|------|------|
| **数据分析** | 上传 CSV，用中文提问；Agent 生成 SQL、在 DuckDB 上执行，前端展示时间线与图表 |
| **简历匹配** | 上传简历，勾选岗位；`resume ∥ job` 并行分析后打分、给技能缺口与解读 |
| **岗位爬虫** | 抓取招聘 JD 入库，可导出 CSV 供分析使用 |
| **可观测** | 全程 SSE 推送执行事件（plan / agent_start / sql / retry / final） |

## 4. 前端结构

### 4.1 App Shell

| 组件 | 文件 | 作用 |
|------|------|------|
| 顶栏 | `app/components/Navbar.tsx` | Logo、主题、设置、用户区 |
| 侧栏 | `app/components/Sidebar.tsx` | 四视图导航；可折叠 |
| 壳层 | `app/components/AppShell.tsx` | Navbar + Sidebar + main |
| 视图状态 | `app/components/workspace-context.tsx` | 四视图切换 |

### 4.2 四视图

| 视图 | 主要内容 |
|------|----------|
| **数据集** | CSV 上传、schema |
| **数据分析** | 提问、时间线、图表、历史 |
| **简历匹配** | 简历 + 岗位 + 结果；右侧日志 |
| **岗位爬虫** | 抓取与导出；右侧日志 |

### 4.3 鉴权（前端）

- 无登录页；自动 register/login 并注入 Bearer。
- 请求前 `ensureAuthToken()`；401 时强制刷新重试。
- 登录限流下有退避。

## 5. 后端 API 与通信

### 5.1 主要路由

| 前缀 | 功能 |
|------|------|
| `/api/auth/*` | 注册 / 登录 / me |
| `/api/datasets` | CSV 上传 |
| `/api/tasks` | 任务、历史、trace、export、**SSE** |
| `/api/resumes` `/api/matches` | 简历与匹配 |
| `/api/crawler/*` | 岗位抓取与导出 |
| `/api/settings` `/api/models` | 开关与 LLM 配置 |
| `/api/health/*` | mysql / redis / duckdb / ready |

### 5.2 通信

```text
前端 ──REST──▶ FastAPI ──▶ Agent Runtime
                  │              │
                  │         事件 buffer
                  │              │
                  ◀──── SSE ─────┘
             （可同时写 MySQL steps）
```

- 控制：REST + JWT  
- 进度：SSE（`agent_start/sql/final` 等）  
- 落库在 API 层，不在 Runtime 内部

| Planner | 按复杂度裁剪路径 |
| Registry | Agent 注册 |
| Executor | 调度、重试、事件 |
| Context Engineering | Token 与 Prompt 构建 |

### 6.2 Agent 角色

| Agent | 职责 | 是否调用 LLM |
|-------|------|----------------|
| data_agent | NL2SQL + DuckDB | 是 |
| resume_agent | 简历画像 | 是（可兜底） |
| job_agent | JD 画像 | 是（可兜底） |
| match_agent | 打分 + 解读 | 解读可 LLM |
| validator_agent | 本地校验 | 否 |
| report_synthesizer | 汇总 | 默认模板 |

### 6.3 真 LLM 判断

- 延迟为秒级（Mock 通常毫秒级）
- SQL 贴合 schema
- 说明**不含**「mock 规则生成」
- 匹配结果 `interpretation_source = "llm"`

### 7.1 步骤表

| 步骤 | 动作 | 存储/位置 |
|------|------|-----------|
| ① | 提交问题 | FastAPI |
| ② | 创建任务 | MySQL `tasks` |
| ③④ | 启动并返回 task_id | HTTP |
| ⑤ | 订阅 SSE | 连接 |
| ⑥ | 路由与规划 | Runtime |
| ⑦⑧ | **LLM 生成 SQL** | 外部模型 |
| ⑨⑩ | **DuckDB 执行** | 引擎 |
| ⑪ | 校验汇总 | Runtime |
| ⑫ | 落库 | MySQL |
| ⑬⑭ | 推送并渲染 | 浏览器 |

### 7.2 设计要点

1. **异步任务**：先返回 `task_id`，不阻塞 HTTP。  
2. **进度与结果分离**：SSE 管进度；完整结果在 MySQL/trace。  
3. **LLM 最慢**：可能超时重试，步骤表可见痕迹。  
4. **Runtime 不写库**：便于测试与扩展。

## 8. 数据层说明

### 8.1 分工

```text
MySQL   — 业务账本（用户、任务、结果、配置）
Redis   — 缓存与幂等锁（可选，可降级）
DuckDB  — 对 CSV 视图执行分析 SQL
```

### 8.2 主要表

| 表 | 内容 |
|----|------|
| `users` | 账号与密码哈希 |
| `datasets` | 数据集元数据 |
| `tasks` | 状态与 `final_result` |
| `task_steps` | Agent 步骤 trace |
| `resumes` / `jobs` / `matches` | 匹配相关 |
| `model_configs` / `app_settings` | LLM 与开关 |

### 8.3 写入方式

- **PyMySQL + 手写 SQL**（`persistence/mysql.py`），非 SQLAlchemy。  
- 同步 DB 调用经 `asyncio.to_thread`。  
- 生成结果由 **API 层 Python 函数** 写入，而非 Agent 直连库。

### 8.4 效率（简）

| 场景 | 结论 |
|------|------|
| 中小规模 / 单机 | 够用，SQL 可控 |
| 真正瓶颈 | 多在 LLM / 外网，而非 MySQL |
| 高并发再优化 | 连接池、批量写 |

## 9. 两条业务链路

### 9.1 数据分析

```text

     ↓
中文提问 → POST /tasks
     ↓
data_agent(LLM) → DuckDB → validator/report
     ↓
final_result → SSE + MySQL → 前端图表

     ↓

     ↓
match 打分与解读 → matches + SSE → 前端展示
```

## 11. 设计原则与边界

| 原则 | 含义 |
|------|------|
| Multi-Agent 为核心 | 链路可解释 |
| Redis 可降级 | 不挡主流程 |
| DuckDB 只做分析 | 不存业务账 |
| MySQL 主库 | 唯一持久账本 |
| Runtime 与存储解耦 | API 层落库 |
| 界面服务体验 | Shell + 四视图 |

| 边界 | 说明 |
|------|------|
| 无业务登录 UI | 默认自动登录，适合本地 |
| 爬虫依赖外网 | 超时可能 502 |
| LLM 延迟波动 | 可能超时后重试 |
